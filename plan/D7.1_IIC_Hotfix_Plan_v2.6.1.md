### H0.1 — `llm_client.bootstrap.router_from_env()`

**File (new):** `packages/llm-client/llm_client/bootstrap.py`

```python
from __future__ import annotations
import os
from llm_client.router import LlmRouter, set_router
from llm_client.adapters import DeepSeekAdapter, AnthropicAdapter, GroqAdapter
from llm_client.cost_meter import CostMeter
from llm_client.rate_limit import TokenBucketRateLimiter
from llm_client.telemetry import LakeLlmCallSink

def router_from_env() -> LlmRouter | None:
    """Construct an LlmRouter from environment variables, or return None
    if no LLM provider is configured.

    Reads:
      DEEPSEEK_API_KEY, DEEPSEEK_BASE_URL, DEEPSEEK_MODEL_PRO, DEEPSEEK_MODEL_FLASH
      ANTHROPIC_API_KEY, ANTHROPIC_MODEL
      GROQ_API_KEY, GROQ_MODEL
      LLM_MONTHLY_CAP_USD (default inf, per P0.3)
      IIC_RATE_DEEPSEEK_PRO, IIC_RATE_DEEPSEEK_FLASH (default 8 rps)
      LAKE_DSN (for the telemetry sink)
    """
    adapters = []
    if k := os.getenv("DEEPSEEK_API_KEY"):
        adapters.append(DeepSeekAdapter(
            api_key=k,
            base_url=os.getenv("DEEPSEEK_BASE_URL", "https://api.deepseek.com"),
            model_pro=os.getenv("DEEPSEEK_MODEL_PRO", "deepseek-reasoner"),
            model_flash=os.getenv("DEEPSEEK_MODEL_FLASH", "deepseek-chat"),
            rate=TokenBucketRateLimiter(
                rate_per_sec=float(os.getenv("IIC_RATE_DEEPSEEK_PRO", "8")),
                burst=16,
            ),
        ))
    if k := os.getenv("ANTHROPIC_API_KEY"):
        adapters.append(AnthropicAdapter(
            api_key=k,
            model=os.getenv("ANTHROPIC_MODEL", "claude-haiku-4-5-20251001"),
        ))
    if k := os.getenv("GROQ_API_KEY"):
        adapters.append(GroqAdapter(api_key=k, model=os.getenv("GROQ_MODEL", "llama-3.3-70b-versatile")))

    if not adapters:
        return None  # caller decides whether this is fatal

    return LlmRouter(
        adapters=adapters,
        cost_meter=CostMeter(monthly_cap_usd=float(os.getenv("LLM_MONTHLY_CAP_USD", "inf"))),
        telemetry_sink=LakeLlmCallSink(dsn=os.environ["LAKE_DSN"]),
    )


def bootstrap_router_or_die(service_name: str) -> LlmRouter:
    """Public entrypoint used by every agent's lifespan hook. Calls set_router()
    so legacy callers via get_router() see the same instance. Raises if no
    provider is configured."""
    router = router_from_env()
    if router is None:
        raise RuntimeError(
            f"{service_name}: no LLM provider configured. "
            "Set at least one of DEEPSEEK_API_KEY / ANTHROPIC_API_KEY / GROQ_API_KEY."
        )
    set_router(router)
    return router
```

**Why this shape:**

1. **`router_from_env()` returns Optional**, not raises. Agents that are happy to run in a degraded mode (e.g. `agent_intelligence` doing ingest-only) can opt out by checking the None.
2. **`bootstrap_router_or_die()` is the agent-default.** Same construction, but raises with a clear message — so the startup error is the *first* thing you see in the container log, not a downstream "skipped" 30 minutes later.
3. **Single source of env-knob truth.** Today the only place that reads `DEEPSEEK_BASE_URL` is `admin_api/connectors.py` (Class C2 in the bringup). After this lands, all agents agree on what env vars matter.
4. **`set_router()` once, at startup.** Matches the existing global router pattern in `llm_client/router.py` and means the legacy `chat()` callers continue to work without code changes.

**Acceptance test:** `tests/llm_client/test_bootstrap.py`

### H1.1 — Pass `user` through `/chat`

**File:** `apps/agent_secretary/agent_secretary/routes_chat.py` (or wherever the `/chat` handler lives — bringup says it's reachable at `POST /chat` on port 8080)

The bringup observed:
```
$ curl :8080/chat -d '{"user":"ziwei","text":"hi"}'
{"user_id":"anon","answer":"(no agents dispatched for: hi)"}
```

Root cause: the handler builds `user_id` from a header / cookie that's not present, falls back to `"anon"`, and never inspects the body. Then `SECRETARY_ALLOWED_USERS=ziwei` (set in compose) never matches.

Fix — accept `user` from either the body or a standard header, prefer the header if both are present (so authenticated callers can't be impersonated by body content), and only fall back to `"anon"` if both are missing:

```python
from fastapi import APIRouter, Header, Request

router = APIRouter()

class ChatIn(BaseModel):
    user: str | None = None
    text: str
    # ... existing fields ...

@router.post("/chat")
async def chat(
    body: ChatIn,
    request: Request,
    x_user_id: str | None = Header(None, alias="X-User-Id"),
):
    user_id = (x_user_id or body.user or "anon").strip().lower()
    # ... allow-list check uses user_id ...
```

Plus a deprecation comment on the `body.user` path so future-us knows to remove it once the dashboard sends `X-User-Id`.

**Update `DEPLOYMENT.md`:** add a row in §2 (agent surfaces) noting that `/chat` accepts either `X-User-Id: <id>` header (preferred) or `{"user": "<id>"}` in the body (compatibility), and that `SECRETARY_ALLOWED_USERS` is a comma-separated allowlist matched case-insensitively against that value.

**Acceptance:**
- `curl -H 'X-User-Id: ziwei' :8080/chat -d '{"text":"hi"}'` → `user_id: "ziwei"` and the planner *attempts* to dispatch (may still fail downstream if H0 isn't landed, but no longer short-circuits on auth).
- `curl :8080/chat -d '{"user":"ziwei","text":"hi"}'` → same result (backward-compat).
- `curl :8080/chat -d '{"text":"hi"}'` → 403 with body `{"detail":"user not in allowlist","user_id":"anon"}`.

**Vibe prompt:** *"In `apps/agent_secretary/agent_secretary/routes_chat.py`, change the `/chat` handler per D7.1 §H1.1: accept user from `X-User-Id` header or body, prefer header, fall back to `anon`. Update DEPLOYMENT.md §2 row for `/chat`. Add an integration test covering all three input cases."*

### H1.2 — `POST /chat/echo` — always-LLM demo endpoint

**File:** `apps/agent_secretary/agent_secretary/routes_chat.py`

This is the smallest possible endpoint that proves the wiring works. It bypasses the planner, the allow-list, the dispatch table, and the persona/fundamental/quant short-circuits that all break in a fresh-checkout environment. Its single job is: take a string, ask the cheapest model to echo it, return both the LLM response and the `llm_call_id` that landed in `lake.llm_calls`.

```python
@router.post("/chat/echo")
async def chat_echo(
    body: ChatEchoIn,
    request: Request,
):
    """Always-LLM demo path. Used by fresh-bringup smoke. Does NOT consult
    the allow-list (so a fresh deploy can prove wiring without configuring users).
    Disable in prod via SECRETARY_DEMO_ENDPOINTS=off."""
    if os.getenv("SECRETARY_DEMO_ENDPOINTS", "on").lower() == "off":
        raise HTTPException(404)
    router_ = get_router()
    if router_ is None:
        raise HTTPException(503, "no LLM router bound — see D7.1 §H0")
    msg = ChatMessage(role="user", content=f"Echo this back verbatim: {body.text!r}")
    resp = await router_.chat_or_raise(
        caller_id="secretary.echo",
        messages=[msg],
        model_tier="flash",  # cheapest available
        max_tokens=64,
    )
    return {
        "echo": resp.content,
        "llm_call_id": resp.call_id,
        "model": resp.model,
        "latency_ms": resp.latency_ms,
    }
```

**Why this design:**
- **Unauthenticated by default** (`SECRETARY_DEMO_ENDPOINTS=on`) so the smoke gate has no allowlist to fight with. Off-switch in prod via env.
- **Cheapest tier** (`flash`) so smoke-checking is free.
- **`chat_or_raise`** so it surfaces real errors (consistent with P0.2 in D7).
- **Returns `llm_call_id`** so the smoke (§H0.3) can assert telemetry on it.

**Acceptance:**
- `curl :8080/chat/echo -d '{"text":"hello"}'` returns `{"echo": "'hello'", "llm_call_id": "<uuid>", ...}` with HTTP 200.
- A matching row exists in `lake.llm_calls` with `caller_id='secretary.echo'`.
- With `SECRETARY_DEMO_ENDPOINTS=off`, the same call returns 404.

**Vibe prompt:** *"Add `POST /chat/echo` per D7.1 §H1.2 in `apps/agent_secretary/agent_secretary/routes_chat.py`. Add an integration test that posts, asserts `llm_call_id != null`, and then queries `lake.llm_calls` to confirm the row."*

### H2.4 — CI lint: forbid hand-created hypertable time-column indexes (R8)

**File (new):** `tools/lint_hypertable_indexes.py`

```python
"""Lint alembic migrations under packages/data-lake/.../migrations/versions/
for the redundant pattern:

    create_hypertable("lake.<t>", "<time_col>")
    op.create_index("<t>_<time_col>_idx", ...)

TimescaleDB's create_hypertable auto-creates a B-tree index on the time
column named exactly <t>_<time_col>_idx. Recreating it manually raises
'relation already exists' at upgrade time.

Twin of tools/lint_hypertable_pk.py (P1.5). Same shape, same value.
"""
import re, sys, pathlib

MIGRATIONS = pathlib.Path("packages/data-lake/data_lake/migrations/versions")
HYPERTABLE = re.compile(r"create_hypertable\(['\"]lake\.(\w+)['\"]\s*,\s*['\"](\w+)['\"]")
INDEX      = re.compile(r"create_index\(\s*['\"](\w+)_idx['\"]")

errors = []
for f in MIGRATIONS.glob("*.py"):
    src = f.read_text()
    for ht in HYPERTABLE.finditer(src):
        table, tcol = ht.group(1), ht.group(2)
        bad = f"{table}_{tcol}"
        for idx in INDEX.finditer(src):
            if idx.group(1) == bad:
                errors.append(f"{f.name}: redundant index '{bad}_idx' — create_hypertable made it.")

if errors:
    for e in errors: print(f"::error::{e}", file=sys.stderr)
    sys.exit(1)
print("OK")
```

Wire into `static-checks.yml`:

```yaml
- name: Lint hypertable indexes
  run: python tools/lint_hypertable_indexes.py
```

**Acceptance:** running on the pre-25f26ae tree of `0007_pgvector_intel_embeds.py` reports the regression. Running on the post-25f26ae tree passes.
