# Session report — v2.6 fresh bring-up on `feat/v2.6-d7-prototype-to-product` — 2026-05-19

> **Scope.** A vibe-coding session that pulled the v2.6 / D7 prototype-to-product branch
> onto a developer box (Ubuntu Desktop 26.04), tried to bring it up end-to-end with
> real API keys, and shipped the fixes that were needed to get there. This is not a
> production incident — it's a record of what the documented "fast path" actually did
> when run on a fresh checkout, what broke, what we patched, and what's still off.
>
> **Branch:** `feat/v2.6-d7-prototype-to-product`
> **Starting commit:** `40cefec` (docs refresh)
> **End-of-session HEAD:** `25f26ae` (migration fixes pushed)
> **Operator:** Ziwei  •  **Pair:** Claude Code

## TL;DR

- Five bugs blocked `make migrate` / `make build` from a clean checkout. All five
  were fixed in two commits during the session ([`fb06e9d`](../../commit/fb06e9d),
  [`25f26ae`](../../commit/25f26ae)) and the stack now reaches 13/13 healthy services
  + a working admin_api on :8090. Migrations 0006 → 0013 apply cleanly.
- Real DeepSeek, FRED, and Polygon keys are validated end-to-end via the
  `admin_api` connector-test endpoints (the keys themselves work).
- **None of the agent "thinking" endpoints actually call the LLM.** `lake.llm_calls`
  is empty after running every probe in the suite. The root cause is that *no
  production code ever calls `set_router()`*, so the global LLM router is unbound
  and every agent's `chat()` call returns a synthetic skip silently. The P0
  cost-breaker-off work has no observable effect because the call never reaches
  the router in the first place.
- D7 should be considered **build-clean but not wiring-clean**. The "thinking
  nodes" were turned into real adapters in P6/P7/P8, but the bootstrap that
  connects them to a credentialed router is still missing.

## What we set out to do

The user-facing goal: pull the just-pushed `feat/v2.6-d7-prototype-to-product`
branch on a fresh dev box, follow the brand-new `README.md` + `DEPLOYMENT.md`
"one command" story (`make setup`), and verify the v2.6 system actually runs
with real API keys.

This is the *exact* scenario that the new `.github/workflows/fresh-bringup.yml`
CI gate is supposed to defend against, and the README's "fresh-Linux bring-up"
table is supposed to summarize. So when it broke, every failure is also a
signal about which class-of-bug those gates aren't catching yet.

### Class A — build-side blockers (commit [`fb06e9d`](../../commit/fb06e9d))

| # | File | Symptom | Cause |

Six sibling packages don't set this; only notifier does. Latent since the original scaffold (`2fc4997`, 2026-05-06) — masked by the old dev-bind-mount workflow that never went through pip install. P1.1's new `iic-base` image unmasked it. |
| A2 | [`apps/dashboard/package.json`](../../apps/dashboard/package.json) | `vite build` fails: `TS2307: Cannot find module 'react-globe.gl'`. | The P5.3 component [`EventGlobe.tsx`](../../apps/dashboard/src/components/EventGlobe.tsx) was added without declaring `react-globe.gl`, its peer dep `three`, or `@types/three` in `package.json`. |
| A3 | [`apps/dashboard/src/components/EventGlobe.tsx`](../../apps/dashboard/src/components/EventGlobe.tsx) | After A2 fix, three additional `TS2322` errors on `pointAltitude` / `pointColor` / `pointRadius` / `pointLabel`. | Accessor types in current `react-globe.gl` are declared as `(obj: object) => T`. The component typed its callbacks as `(d: { size: number }) => number` etc., which TS refuses to narrow into the lib's signature. |

### Class B — migration-side blockers (commit [`25f26ae`](../../commit/25f26ae))

| # | File | Symptom | Cause |
|---|---|---|---|
| B1 | [`packages/data-lake/data_lake/migrations/versions/0007_pgvector_intel_embeds.py`](../../packages/data-lake/data_lake/migrations/versions/0007_pgvector_intel_embeds.py) | `make migrate` fails on 0007: `permission denied to create extension "vector"`. | `iic_migration` isn't a Postgres superuser, and `vector` (pgvector) isn't in the PG "trusted extension" allow-list. `timescaledb` and `pg_partman` (used in migration 0001) work because they ARE trusted in the `timescaledb-ha` image — pgvector ships pre-built but not pre-trusted. Fix: pre-create the extension in [`infra/postgres/init-roles.sql`](../../infra/postgres/init-roles.sql), which already runs as the superuser via `run-migrations.sh`. |
| B2 | [`0007_pgvector_intel_embeds.py`](../../packages/data-lake/data_lake/migrations/versions/0007_pgvector_intel_embeds.py) and [`0010_lake_geo_events.py`](../../packages/data-lake/data_lake/migrations/versions/0010_lake_geo_events.py) | After B1 fix: `make migrate` fails again on 0007 with *"relation `intel_embeds_ts_idx` already exists"*, then on 0010 with the same shape for `geo_events_ts_idx`. | TimescaleDB's `create_hypertable(t, time_col)` auto-creates a B-tree index on the time column named `<table>_<time_col>_idx` (here: `intel_embeds_ts_idx`, `geo_events_ts_idx`). 0007 and 0010 then explicitly tried to `CREATE INDEX` an index with the same name, causing a collision. Other v2.6 migrations (0008/0009/0012/0013) named their secondary indexes `<table>_<colA>_<colB>_idx` so they didn't collide. |

### Class C — runtime / wiring (not fixed)

| # | Where | Observable | Underlying issue |
|---|---|---|---|
| C1 | every agent's `main.py` | Every probe of `/run/*` / `/chat` returns either an empty/placeholder response or `skipped`. `SELECT COUNT(*) FROM lake.llm_calls` is `0` after exercising the full smoke matrix. | **No production code anywhere in `apps/` calls [`set_router()`](../../packages/llm-client/llm_client/router.py).** Agents call `chat()` from `llm_client`, which calls `get_router()` internally; with nothing registered, the legacy `chat()` returns a synthetic skip (rather than the new `chat_or_raise()` which would raise `NoLLMAvailable`). Result: P0's cost-breaker-off and `chat_or_raise()` work is invisible because the LLM call never reaches them. |
| C2 | `llm_client` package | The only place in the repo that reads `DEEPSEEK_API_KEY` is [`apps/admin_api/admin_api/connectors.py:54`](../../apps/admin_api/admin_api/connectors.py#L54) (the connector-test endpoint). | The LLM client has no env-driven factory — nothing reads `DEEPSEEK_BASE_URL` / `DEEPSEEK_MODEL_PRO` / `ANTHROPIC_API_KEY` etc. to construct a router. C1 and C2 are two faces of the same gap. |
| C3 | secretary `/chat` | Request body `{"user":"ziwei","text":"..."}` returns `"user_id":"anon"` and `"answer":"(no agents dispatched for: ...)"`. | The endpoint discards the body's `user` field and falls back to "anon". `SECRETARY_ALLOWED_USERS=ziwei` (which the compose anchor sets) consequently never matches, and the planner short-circuits **before** ever attempting an LLM call. So even if C1 were fixed, `/chat` would still no-op for any client that doesn't somehow flip `user_id` to "ziwei". |
| C4 | `docker compose restart` after editing `.env` | After pasting keys into `.env` and `restart`-ing agents, env vars inside the container were still empty (`echo ${#DEEPSEEK_API_KEY}` → `0`). | `docker compose restart` does **not** re-create containers; env is baked at container *create* time. Required `docker compose up -d` (which only re-creates services whose config changed). DEPLOYMENT.md §4 "Legacy path" tells the user to `restart` after `sed`-ing the .env, which won't actually work. |
| C5 | `deploy/smoke-check.sh` | `make health` doesn't probe `:8090` even though `admin_api` is in the default profile per DEPLOYMENT.md §2 ("14th container"). | The smoke list pre-dates D7's admin_api and wasn't extended. |
| C6 | most agent endpoints | Persona `/run/daily` → `"persona digest + memory not yet bound; reasoner skipped"`. Fundamental `/run/cover/AAPL` → `{"filings_n": 0}`. Board `/decide` → `flag_disabled`. Quant `/run/signal` → `regime: "unknown"`, empty factors. | Heavy upstream gating: each agent skips its LLM path if its prerequisite data / flag isn't there. Even if C1 + C2 + C3 were fixed, a fresh checkout has *no* way to exercise the LLM path without first booting the intel pipeline, populating filings, or flipping flags. There's no "demo" endpoint that always exercises the LLM path. |

iic=# SELECT COUNT(*) FROM lake.llm_calls;

The full conclusion of the in-session smoke test: **the keys work, the provider
APIs work, but the agents never actually call them.** Every short-circuit above
hides the LLM-bootstrap gap behind a sensible-looking "no inputs" / "skipped" /
"flag_disabled" response.

## Issues to address in further development

Listed in priority order. Severity = effect on whether v2.6 is actually a
prototype-to-product cut or still a substrate-only cut.

### P0 — blocks calling D7 "done"

**R1. Bootstrap an `LlmRouter` at agent boot.** *(Class C1 + C2)*

- Add a factory in `packages/llm-client/` (e.g. `llm_client.bootstrap.router_from_env()`)
  that reads `DEEPSEEK_API_KEY` / `DEEPSEEK_BASE_URL` / `DEEPSEEK_MODEL_*` /
  `ANTHROPIC_API_KEY` / `GROQ_API_KEY` / `LLM_MONTHLY_CAP_USD` and constructs a
  `LlmRouter` with the right primary chain + fallback chain + `RateLimiter` +
  `CostMeter` + telemetry sink.
- Call it from each FastAPI agent's `lifespan` (startup hook) in
  `apps/agent_*/.../main.py`, then `llm_client.router.set_router(router)`.
- After this lands, P0's cost-breaker-off / `chat_or_raise` work becomes
  observable instead of decorative.

**R2. Add a fresh-bringup smoke that *requires* at least one row in `lake.llm_calls`.**

The current `make health` / smoke-check is structural — it asks every service
"are you up?" It would happily pass forever even if the LLM router were unbound,
because no one queries `lake.llm_calls` to assert "we got at least one round-trip."
A 2-line addition to `deploy/smoke-check.sh` that hits `/admin/connectors/deepseek/test`
(and asserts `state: ok` when the key is set, `unconfigured` when it isn't) plus an
optional `SELECT COUNT(*) FROM lake.llm_calls` would have caught the wiring gap
during the D7 merge.

### P1 — needed for the demo path to mean anything

**R3. Pass `user` through `/chat`, or document the actual auth surface.** *(Class C3)*

- Either: read `user` from the request body and use it for the allow-list check.
- Or: read it from a standard header (`X-User-Id`) and document that
  `{"user":...}` in the body is a no-op.
- Whichever is right, `SECRETARY_ALLOWED_USERS` is only meaningful if the
  endpoint *can* match a user. Right now it can't.

**R4. Provide a deterministic "always-LLM" demo endpoint.** *(Class C6)*

- Most `/run/*` paths skip the LLM when their prerequisites aren't loaded. That's
  the right production behaviour but it makes proving the system *works* on a
  fresh checkout impossible without spending a day populating data.
- A single endpoint like `POST /chat/echo` on secretary that always dispatches
  to persona-flash and returns the LLM round-trip would let the bring-up CI
  prove the wiring end-to-end in two seconds.

### P2 — quality of life / drift prevention

**R5. Fix DEPLOYMENT.md §4 "Legacy path".** *(Class C4)*

Change `docker compose restart …` to `docker compose up -d …` (compose detects
config changes and recreates just the affected services). Add a callout that
`restart` does not reload env. This will save the next person who tries the
documented path the half-hour it cost this session.

**R6. Add `admin_api` to `deploy/smoke-check.sh`.** *(Class C5)*

One line. DEPLOYMENT.md already promises it.

**R7. Add a CI lint for `package-mode = false`.** *(Class A1)*

The notifier bug was latent for two weeks because the dev workflow never
exercised `pip install -e ./packages/notifier`. After P1.1 it does, but the
fresh-build wasn't tested in `.github/workflows/fresh-bringup.yml` against a
docker cache that had been wiped. A trivial grep gate in `static-checks.yml`:
`! grep -r "package-mode\s*=\s*false" packages/` would have caught it instantly.

**R8. Add a CI lint for redundant hypertable time indexes.** *(Class B2)*

P1.5 added [`tools/lint_hypertable_pk.py`](../../tools/lint_hypertable_pk.py)
for the *primary-key-must-include-time-column* class of bug. The companion lint
— *don't recreate the `<table>_<time>_idx` index that `create_hypertable` already
makes* — is the same shape (alembic-time, regex-detectable, deterministic).
Worth a 30-line addition. Two regressions in the 8 new v2.6 migrations is enough
to justify the gate.

**R9. Pin `react-globe.gl` peer-dep set in the iic-base CI image cache.** *(Class A2/A3)*

The dashboard's `npm install` happens fresh in every build (no `npm ci` —
`package-lock.json` isn't even COPYed into the build context). That means a
release of `react-globe.gl` with a different accessor signature would break the
build with no code change on our side. Either switch to `npm ci` (forces
lockfile use) or move the dashboard to an `iic-frontend-base` image with
node_modules baked in. The TS errors we saw (A3) are exactly this class.

### P3 — nice to have

**R10. Document which agent endpoints are LLM-bound vs. data-gated.**

The OpenAPI surface advertises `/run/cover/{ticker}` but doesn't tell you that
a fresh DB returns `filings_n=0` without an LLM call. A note in DEPLOYMENT.md
§2 ("agent surfaces") on which routes need which upstream data would have saved
the smoke-test phase of this session.

## Appendix A — exact command sequence that worked

This is what `make setup` *would have done* if the documented one-command path
had reached the docker stage on this box (it didn't — `setup.sh` requires
interactive sudo and the OS-level markers were already set from a prior run).
After the fixes in this session it does run cleanly; on a truly fresh box,
`make setup` should now succeed end-to-end.

```bash
git pull origin feat/v2.6-d7-prototype-to-product

# Build (iic-base first because every agent FROM-s it)
docker compose -f docker-compose.yml -f docker-compose.dev.yml --profile build-only build iic_base
docker compose -f docker-compose.yml -f docker-compose.dev.yml build

# Bring up
make up

# Migrations 0001 → 0013 (idempotent; pre-creates vector extension via init-roles.sql)
make migrate

# Verify
make health
curl -s http://localhost:8090/admin/health

# Paste keys into .env, then RECREATE (not restart):
docker compose -f docker-compose.yml -f docker-compose.dev.yml up -d --force-recreate \
  orchestrator agent_intelligence agent_secretary agent_persona agent_fundamental \
  agent_quant agent_board agent_backtest admin_api

# Validate keys
curl -s -X POST http://localhost:8090/admin/connectors/deepseek/test
curl -s -X POST http://localhost:8090/admin/connectors/fred/test
```

## Appendix B — what's still broken after this session

Quoting `lake.llm_calls` after the full smoke suite:

```
iic=# SELECT COUNT(*) FROM lake.llm_calls;
 count
-------
     0
(1 row)
```

This number should be `≥ 1` after a real bring-up. The fact that it isn't is
the single most important finding of this session, and is exactly what
recommendations R1 + R2 are about. Until those land, every claim that "P6/P7/P8
turned the thinking nodes into real implementations" is true at the *adapter*
layer but false at the *bootstrap* layer — and the cost-breaker / `chat_or_raise`
work in P0 has no observable effect because the call site never reaches the
router.
