# Workflow 21 — Dashboard UI

> **Depends On:** `02_DATA_LAYER.md`, `05_DATA_BUS_AND_SCHEMAS.md`, `14_AGENT_BACKTEST.md`, `15_AGENT_SECRETARY.md`.
> **Owns:** `apps/dashboard/` — the React+Vite web UI. The deep-dive surface; not the primary push channel (WeChat is).
> **Status:** Final.

---

## 1. Purpose

A single-page React app (Vite) for desk-style, deep-dive use. WeChat is the principal's mobile UX; the dashboard is for the laptop. It must:

1. Render today's brief, all open advices, and the leaderboard at a glance.
2. Subscribe to NATS via a WebSocket bridge for live updates.
3. Allow chatting with the Secretary in `/chat` (SSE).
4. Show host + container metrics inline (no need to bounce to Grafana for routine glances).
5. Render reasonably on a phone for cases where WeChat isn't available.

---

## 2. Ground Truth

### 2.1 Tech stack

- **Vite 5 + React 19**.
- **TypeScript 5** strict.
- **Tailwind CSS** (utility) + **shadcn/ui** for primitives.
- **Recharts** for charts. **TanStack Query** for data. **Zustand** for tiny global state. **react-router-dom** for routing.
- **NATS WebSocket** via `nats.ws`. Auth via short-lived JWT minted by the orchestrator's `/dashboard/token` endpoint.
- **Server-Sent Events** for `/chat`.

### 2.2 Pages

| Route | Title | Purpose |
|-------|-------|---------|
| `/` | Home | Today's brief + 5 most recent advices + leaderboard top-3 |
| `/leaderboard` | Leaderboard | Per-agent ranking + stat-sig flags |
| `/agents/:agent` | Agent feed | All advices from one agent + attribution |
| `/tape` | Live trade tape | Open positions + live marks + recent fills |
| `/intel` | Intelligence | Heatmap, headline ticker, country-risk dial, BDI/oil/VIX gauges, bias-balance chart |
| `/quant` | Quant | Factor matrix, regime weights, walk-forward chart |
| `/fundamental` | Fundamental | Watchlist, recent valuations, citation viewer |
| `/personas` | Personas | Persona cards with stats; click → that persona's `/agents/persona.<slug>` |
| `/chat` | Chat | Secretary SSE chat, tone slider |
| `/health` | Health | Host metrics, container statuses, LLM cost, eval drift |
| `/admin/watchlist` | Watchlist Admin | Edit `watchlist.yaml` (writes via PR-style proposal flow) |

### 2.3 Auth

- Local-only by default (Tailscale-protected). Single-user.
- For Cloudflare-Tunnel exposure: Cloudflare Access in front, identity = email allowlist.

### 2.4 Live data

- NATS `intel.dashboard.v1` for the Home + Intel tabs.
- NATS `backtest.daily.v1` and `backtest.leaderboard.v1` for ranking pages.
- NATS `advice.>` (filtered) for the Tape and Agent feeds.
- HTTP polling (TanStack Query, 30s) as a fallback when WS reconnects.

## 5. Workflow Steps

### Step 5.1 — Scaffold

`npm create vite@latest apps/dashboard -- --template react-ts`. Add Tailwind, shadcn/ui, react-router, TanStack Query, Recharts, Zustand, nats.ws.

Add `make codegen-ts` step to import `packages/schema/ts/*` (already generated by the schema package). All NATS payloads are typed end-to-end.

### Step 5.2 — Layout shell

Top app bar with: brand mark · current `macro_regime` badge · cost burn pill · tone slider · profile menu. Sidebar nav for the routes in §2.2. Body uses container width up to `max-w-screen-2xl`.

### Step 5.3 — Home page

Three columns on wide screens, stacked on narrow:

- **Left:** today's brief (from `intel.brief.v1`, rendered as Markdown).
- **Center:** "Today's Advices" — top 5 by confidence, each as an `AdviceCard` with thesis + bands + agent badge.
- **Right:** leaderboard top-3 with per-agent sparkline of last 30 d cumulative pnl_r.

### Step 5.4 — Leaderboard page

Sortable table: agent · score · Sharpe (with CI bar) · hit_rate · R_avg · max_DD · stat_sig · provisional. Filter by agent class (fundamental/quant/persona). Color the row green/red against the smart-passive benchmark.

### Step 5.5 — Trade tape

Live list of open positions; a small per-position chart of entry/mark/target/stop. Recent fills below.

### Step 5.6 — Intel, Quant, Fundamental, Personas, Chat, Health, Admin

- **Intel**: heatmap of news mentions by region; bias-balance pie; macro thesis card; commodity gauges.
- **Quant**: factor matrix grid (color-mapped), regime weights radar chart, walk-forward equity curve.
- **Fundamental**: watchlist table with last-touched, last-thesis-snippet; click into a CitationViewer that highlights the chunk in the filing.
- **Personas**: per-persona card (avatar generated from initials, NOT a likeness photo) showing recent advices, win rate, and a bias chart.
- **Chat**: SSE-streamed Secretary chat; tone slider in the corner.
- **Health**: host metrics (CPU temp, NVMe wear/temp, RAM, disk free, UPS battery), container status grid, LLM spend last 30 d, eval drift indicator.
- **Admin → Watchlist**: paste-and-validate a YAML edit; submit creates a Git PR via the repo's GitHub Actions (no direct write).

### Step 5.7 — NATS WebSocket bridge

The NATS server itself supports WS (`-js` plus `--websocket`). Token minted by orchestrator's `/dashboard/token` (short-lived JWT). Client uses `nats.ws.connect({servers: "wss://iic-host/nats", token: ...})`.

🧪 **VIBE-PROMPT — NATS WS in browser:**
> Implement `src/lib/nats.ts` using `nats.ws`. Connection bootstrap fetches a token from `/api/dashboard/token`. Provide a `useSubscription(subject)` React hook that yields parsed Pydantic-derived TS types. Cleanup on unmount.

### Step 5.8 — Chat (SSE)

Consume `secretary./chat` SSE stream. Render markdown progressively. Tone slider state synced to KV via `/api/secretary/tone` PUT.

### Step 5.9 — Empty/loading/error states

Every route handles three states. Use shadcn `Skeleton` for loading. Empty states explain what would populate (e.g., "No advices today — agents are awaiting the next digest").

### Step 5.10 — Mobile responsiveness

Aim for usable, not pretty, on phones — WeChat is the phone UX. Tabs collapse to a drawer below `md`. The Home, Leaderboard, and Chat pages are most important on mobile.

### Step 5.11 — E2E tests

Playwright tests: Home renders within 5 s with mock data; Chat sends a message and receives a streamed response; Leaderboard filtering works.

## 8. Risks & Gotchas

⚠️ **NATS in browser auth.** Don't expose long-lived NATS creds. Always use the short-lived JWT minted by the orchestrator. Token TTL ≤ 5 min, refresh in the client.

⚠️ **Bundle size.** Recharts + TanStack Query + nats.ws + shadcn primitives can balloon. Set a 250 KB budget for the initial bundle (gzipped); code-split per route.

⚠️ **Markdown XSS.** Rendering `intel.brief.v1` markdown — use `react-markdown` with `rehype-sanitize`, never `dangerouslySetInnerHTML`.

⚠️ **Time zones.** All timestamps from the bus are UTC ISO-8601. Render in user's local TZ via `Intl.DateTimeFormat`; never hand-roll.

⚠️ **Persona avatar likenesses.** Don't use real photos of named investors. Use stylized initials avatars; document this in code comments tied to the disclaimer rule.

⚠️ **Watchlist admin write path.** The admin page must not write directly to the file. It POSTs a PR proposal which a CI bot turns into a PR. Manual review remains a gate.

⚠️ **WebSocket on cellular.** WeChat is the phone story; WS may be flaky on cellular. The dashboard transparently falls back to polling when the connection drops more than twice in 30 s.

⚠️ **Schema drift.** If the Python schemas change, regenerate TS types and rebuild. CI fails if `packages/schema/ts` is out of date.
